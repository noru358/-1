## 1. 맥락 (요약 사본, 원본: DESIGN.md 2~7장)

### 1.1 누가, 어떤 상황에서 (기반)
- **만드는 사람**: 1인 인디 개발자. 따로 서울나이트워치(탑다운 액션 RPG, `noru358/watch`)를 만들고 있다.
- **규모**: 혼자 2~3개월. 코드는 Claude가 맡고, 도트는 사용자가 다듬는다. 그래서 콘텐츠는 규칙과 데이터로 늘리고 그림은 적게 쓴다.
- **본편과의 관계**: 일단 별개로 만든다. 나중에 본편의 자동전투와 비동기 교류 시스템으로 합칠 가능성을 염두에 둔다.
- **세계관**: 자유. 지금은 "컴퓨터 속 AI 에이전트 회사"다(이름, 세계관 확정은 DESIGN 11장 열린 질문).

### 1.2 밥 먹으면서 하는 게임 (기반)
- **상황**: 밥 먹을 때 유튜브를 보듯이, 틀어 두면 혼자 계속 돌아가고 계속 보게 되는 화면. steamcity(odwo.kr)의 살아 움직이는 야경이 출발점이었다.
- **조작 기준**: 젓가락을 내려놓지 않고 할 수 있어야 한다.
  - 젓가락 든 채로 툭 누르거나, 왼손으로 키보드나 마우스를 쓰는 정도.
  - 설계는 멈춘 상태에서 차분히 해도 된다. 지켜보는 동안의 개입은 한 번 누르기.
- **시간**: 한 번 15분 정도, 또는 틀어 놓고 잊기.
- **압박**: 없거나 약하게(마감, 넘침). 망하게 하지 않는다.
- **소리**: 없어도 되고, 잘 만들면 좋다. 끄고 켤 수 있으면 된다.
- **기기**: 전부. PC는 옆 모니터나 작은 창, 폰은 세로.

### 1.3 재미의 핵심 (기반)
- 간단한 조작, 다음 목표가 보이는 노드나 해금, 오래 봐도 편한 도트와 글꼴(갈무리).
- **선택이 있어야 다시 한다.** barnfix(소 잃고 외양간 고친다)는 가장 싼 것만 사도 엔딩까지 가서 한 번 하면 끝이었다.
- **작업이 이루어지는 과정이 눈에 보이는 것.** 꼬물이가 일감을 들고 와서 어디에 놓고, 어디서 받고, 어디서 만드는지 전체가 보이는 것.
- **오밀조밀하고 작고 귀여운 애들이 바쁘게, 체계적으로 일하는 세계.** Claude Code의 Clawd 같은 작은 생물, 세피리아의 귀여운 도트.
- **그럴듯한 규칙**: 막 만든 규칙이 아니라 사람이 봤을 때 어색하지 않은 규칙. 실제 업무 구조를 참고한다.
- **취향은 대중적이고 진입장벽은 낮게, 내용(게임성, 성장, 이야기)은 깊게.**
- **설계 → 지켜보기 → 막힌 곳 찾기 → 다시 설계.** 기능 블록(접수함, 검색실, 작성실, 검수대 ...)을 회로처럼 잇고 짠다.
- **결정은 드물고 느리게, 결과는 오래 보이게.**

### 1.4 그림 기준 (원칙은 기반, 숫자는 현재)
- **시점**: 탑뷰(위에서 살짝 내려다본 2D). 옆에서 보는 화면은 흐름이 한 줄로 묶여서 버렸고, 3D는 규모상 보류했다.
- **크기 (현재)**: 꼬물이 16px, 타일 24px, 판 16×9칸(384×216).
  - 근거: 세피리아 실측(토끼 키 약 12px, 화면 약 320×180), 크기 비교 판 → REFERENCES B.
- **도트 작업 방식**: 코드로 도트 초안을 찍고(팔레트, 외곽선, 빛 방향을 규칙으로 고정) Aseprite에서 손본다. AI 그림은 분위기와 큰 그림용.
- **글꼴**: 갈무리11(SIL OFL). 쓰는 글자만 잘라 base64로 한 파일에 넣는다.
- **색**: 어두운 판 위에 켜진 것만 밝게.
  - 부품 색: 자료 `#8ac8ff`, 글 `#f4f1ff`, 그림 `#ff9ad0`, 표 `#f0e070`
  - 결과물: `#ffe27a`

## 4. v4 게임 명세 (현재)

### 4.1 한 줄
인간이 AI에게 맡긴 주문을, 컴퓨터 속 꼬물이 에이전트들이 부품(자료, 글, 그림, 표)으로 나눠 만들고 조립실에서 조립해 보낸다. 플레이어가 하는 일은 세 가지다.
- 방과 길을 회로처럼 배치한다.
- 조립실마다 받을 주문을 정한다.
- 꼬물이들의 분업을 정한다.

### 4.2 화면
- **위**
  - 날짜, 오늘 지표(처리, 평균 시간, 검수 통과, 유지비)
  - **다음 목표 카드**: 주문 이름 + 부품 칩 + 진행 칸 + "열림 → 보상"
  - 하루 진행 막대
- **가운데**: 16×9 타일 판. 판 위 글자는 HTML이다.
  - 방 이름
  - 줄 수("줄 n")
  - **조립실 진행판**: 맡은 주문마다 부품 칩이 한 줄씩 나오고, 채워진 칩 = 도착, 점선 칩 = 아직. "오는 중" 표시도 있다.
  - 접수함 "주문 n/용량" (넘치기 직전이면 빨갛게 깜빡임)
  - 막힌 꼬물이의 이유
- **툴팁**: 방이나 꼬물이 위에 마우스를 올리면 나온다.
  - 방: 하는 일, 기본 시간, 지금 일하는 수와 줄, 조립실이면 맡은 주문 수와 안 받는 주문
  - 꼬물이: 역할, 하는 일, 방별 숙련
- **아래 도구**: 고르기 S, 길 깔기 R, 길 지우기 E, 멈춤 Space, 빠르게 F(×1, ×2, ×3). 남은 길, 꼬물이 수(노는 수), 놓을 방.
- **아래 왼쪽**
  - **주문 카드**: 주문마다 필요한 부품 칩(색 + 한 글자: 자, 글, 그, 표)
  - "칩 = 어느 방에서 만드는지 → 조립실 → 검수대 → 발송구" 한 줄
  - 방송 띠
- **아래 오른쪽**: **분업판**(모드 세 개, 역할별 인원과 +/−), 꼬물이 목록(이름, 역할과 고정 여부, 대표 숙련 ★, 지금 하는 일 또는 노는 이유).
- **하루 보고(종이)**: 지표 표(오늘, 어제, 최고, ▲▼), 진단, 카드 두 장.

**부품 칩**은 화면 전체에서 같은 기호다. 주문 카드, 목표, 조립실 진행판, 부품 방의 큰 색 네모, 꼬물이가 들고 가는 색 네모가 모두 같은 색이다.

### 4.3 조작
| 입력 | 하는 일 |
|---|---|
| 방 클릭 | 설정 창: 설명, 조립실은 받을 주문 켜고 끔, 옮기기 |
| 옮기기 → 빈 칸 클릭 | 그 칸에 놓기 (Esc나 우클릭은 원래 자리로) |
| R + 누르기/끌기 | 길 깔기 (남은 길에서 차감) |
| E + 누르기/끌기 | 길 지우기 (되돌려 받음) |
| Space | 멈춤 / 계속 |
| F | 속도 ×1 → ×2 → ×3 |
| 분업판 모드 버튼 | 자유 / 알아서 분업 / 직접 분업 |
| 역할 +/− | 직접 분업에서 역할 인원 조절 |
| 꼬물이 이름 클릭 | 그 꼬물이 역할을 하나씩 바꿔 고정, 한 바퀴 돌면 해제 |
| 1, 2 | 하루 보고의 카드 고르기 |

한글 자판 상태에서도 같은 키가 동작한다(ㄱ, ㄷ, ㄴ, ㄹ).

### 4.4 판과 길
- 칸 하나 = 길, 방, 빈 칸 중 하나.
- 꼬물이는 **길 칸으로만** 걷고, 목적지 방 칸에만 들어간다(4방향 BFS).
- 처음 판
  - 접수함 (0,4), 발송구 (15,4). 둘 다 고정이다.
  - 가운데 줄 (1..14, 4)에 길 14칸.
  - 검색실 (3,3), 작성실 (6,5), 조립실 (9,3), 검수대 (12,5).
  - 남은 길 16칸, 꼬물이 5마리.
- 방은 빈 칸에 놓는다. 길 옆이 아니면 "길을 이어 주세요"라고 알린다.

### 4.5 방
| 방 | 하는 일 | 기본 시간 | 비고 |
|---|---|---|---|
| 접수함 | 주문서가 쌓임 | - | 고정. 용량 8(카드로 +4) |
| 발송구 | 결과물 내보냄 | - | 고정 |
| 검색실 | 자료 | 2.0초 | |
| 작성실 | 글 | 2.4초 | |
| 그림실 | 그림 | 3.0초 | 목표 1에서 열림 |
| 계산실 | 표 | 2.0초 | 목표 2에서 열림 |
| 조립실 | 주문서를 맡고, 부품이 다 모이면 조립 | 1.0초 + 부품당 0.4초 | 맡는 주문 3개. **안 받을 주문(거부 목록)**을 고름. 새로 열리는 주문은 기본으로 받음 |
| 검수대 | 결과물 확인 | 1.0초 | 실패 18%(카드로 ×0.6) → 조립실에서 다시 조립(0.8초) 후 다시 검수 |

- 일하는 방은 **한 번에 한 마리**만 쓴다. 나머지는 문 앞 길에서 줄을 선다.
- 숙련: 그 방에서 일 5번마다 ★ 하나, 최대 ★3. ★당 일 시간 −12%.

### 4.6 주문(레시피)
| 주문 | 부품 | 열리는 때 |
|---|---|---|
| 질문 답변 | 자료 1 + 글 1 | 처음 |
| 그림 요청 | 자료 1 + 그림 1 | 목표 1 |
| 가계부 | 표 2 | 목표 2 |
| 발표 자료 | 자료 2 + 표 1 + 그림 1 | 목표 3 |
| 보고서 | 자료 2 + 표 1 + 글 1 | 목표 4 |
| 블로그 글 | 글 2 + 그림 1 | 목표 5 |

### 4.7 일감 시스템
일감 = 행동 목록이다. 행동은 `{목적지를 고르는 함수, 동작: work | take | drop | deliver}`이고, 목적지는 **행동을 시작할 때** 고른다(방이 옮겨져도 맞게 간다).

놀고 있는 꼬물이는 0.3초마다 일감을 찾는다. 순서는 **끝낼 것부터**다.
1. **조립**: 부품이 다 모인 주문 → 조립실에서 조립 → 검수대 → 발송구.
2. **부품**: 조립실에 놓인 주문 중 아직 아무도 만들지 않는 부품 → 그 부품 방에서 만듦 → 그 주문의 조립실에 놓음.
   - 오래된 주문이 먼저다. 그 방 숙련 ★당 6초를 앞당긴다.
3. **배부**: 접수함 주문서 → 받을 수 있고 자리가 남은 조립실(가까움 + 맡은 수 × 2칸)로.

**방 고르기(부하 분산)**: 점수 = 걷는 칸 ÷ (2.6 × 걷기 배율) + **부하** × 그 방 시간. 부하 = 일하는 중(1) + 줄 + **그 방으로 일하러 오는 중인 꼬물이 수**. 오는 중인 꼬물이까지 세서, 같은 방이 여러 개면 빈 곳으로 고르게 퍼진다.

**노는 이유**는 꼬물이 머리 위(z 표시)와 목록에 뜬다.
- 일 없음
- 맡은 일(역할) 없음
- ○○ 가는 길 없음
- ○○을 받는 조립실 없음
- 조립실 자리 없음

### 4.8 분업
| 모드 | 동작 |
|---|---|
| 자유 | 누구나 아무 일 |
| 알아서 분업 | 5초마다 역할별 **할 수 있는 밀린 일의 양**을 재서 인원을 비례 배분한다. 역할은 "부드럽다": 내 역할 일이 없으면 다른 일을 돕는다 |
| 직접 분업 | 플레이어가 역할별 인원을 +/−로 정한다. 역할은 "엄격하다": 맡은 일만 한다 |

- **역할**: 배부, 자료, 글, 그림, 표, 조립·검수. 부품 역할은 그 방이 있어야 나온다.
- **배정**: 그 역할 숙련이 높은 꼬물이부터, 지금 역할은 되도록 유지한다.
- **고정**: 꼬물이를 누르면 역할이 고정되고 자동 배정에서 빠진다.
- **밀린 일의 양**
  - 부품 = 남은 부품 수 × 그 방 시간
  - 조립 = (준비된 주문 + 조립 중) × 3초
  - 배부 = min(접수함 대기, 조립실 빈자리) × 3초. 조립실이 꽉 차 있으면 배부는 할 수 있는 일이 아니라서 0이다.
- 머리 위 작은 색 점 = 역할(부품 색, 조립은 연두, 배부는 파랑).

### 4.9 하루, 수요, 압박
- **하루 60초.** 속도 ×2, ×3은 같은 틱을 여러 번 돌린다.
- **주문 도착률**(초당) = (0.13 + 0.025 × (날 − 1) + 0.02 × 달성한 목표 수) × (0.85 + 0.3 × sin(하루 진행 × 2π − 1)).
- 접수함(배부 전 주문서)이 용량만큼 차면 새 주문을 놓친다. 게임 끝은 없다.
- **경고**: 용량 −2 이상이면 테두리가 깜빡이고 "곧 넘침"이 뜬다.

## 5. 구현 구조

### 5.1 원칙 (요약 사본, 원본: DESIGN.md 7장)
**모든 개발은 모듈화하고 구조 단계로 처리한다. 하드코딩하지 않는다.** 하드코딩은 어쩔 수 없거나, 게임 특성상 그게 훨씬 나을 때만 한다.
- 숫자와 글은 `00_data.js` 표에만 둔다. 새 방, 부품, 주문, 목표, 카드, 역할은 표 한 줄로 추가한다.
- 저장하는 것은 "사실"(누가 무슨 일감을 쥐었나, 주문이 어디 있나)뿐이다. 부하, 만드는 중인 부품 수, 조립실 자리는 **매 틱 다시 계산**한다(`Derive`). 그래서 숫자가 새서 생기는 교착이 원천적으로 없다.
- 일을 맡기 전에 갈 수 있는지 확인한다. 못 가면 이유를 보여 준다. 방을 들면 그 방의 일을 되돌린다. 편집 중에도 시간은 흐른다.
- 허용 목록이 아니라 **거부 목록**을 쓴다. 새로 생기는 것은 기본으로 허용된다(v3의 "블로그 글 0/8 멈춤" 버그 원인).
