  - 분업 정하기

## 4. 사용자와 일하는 법 (지금까지 확인된 것)
- **언어**: 답은 한국어로 한다. 쉬운 말, 짧은 문장. 사용자는 오타가 많은 편이니 뜻으로 읽는다.
- **질문은 한 번에 몰아서** 한다. 번호를 붙여 묻고, 답하기 쉽게 보기를 준다.
- **형태를 가두지 말고 열어 두고** 생각한다. 피벗해도 된다. 사용자의 말에 Claude가 과하게 꽂히는 것을 싫어한다(예: "타이쿤"이라는 말에 꽂혀 방 배치 게임만 낸 적이 있다).
- **레퍼런스를 찾아 해부하고 역설계해서 구조를 따오는 방식**을 좋아한다. 기획이 얕으면 이걸 먼저 제안한다.
- **개발 원칙**: 모든 개발은 모듈화하고 구조 단계로 처리한다. **하드코딩 금지**(어쩔 수 없거나 그게 훨씬 나을 때만). 숫자와 글은 데이터 표에. → DESIGN 7장
- **확인한 것과 못 한 것을 정직하게** 구분해서 말한다. 봇으로 확인한 것과 사람이 해 봐야 아는 재미를 나눈다.
- **시제품 피드백은 화면 캡처와 함께** 온다. 버그 제보가 오면 먼저 재현해서 원인을 찾고, 원인을 설명한 다음 고친다.
- 사용자가 좋아한 것: 과정이 눈에 보이는 것, 회로 설계 느낌, 작고 귀여운 꼬물이, 칩처럼 통일된 기호, 분업.
- 사용자가 지적한 것: 직관적이지 않은 비유, 안 읽히는 글과 작은 점, 작업자가 노는 것, 한 곳으로 몰리는 것, 얕은 구조, 너무 긴 하루.

## 6. 개발 환경 메모
- **빌드**: `python3 build.py <Galmuri11.woff2> agents agents.html` (`pip install fonttools brotli` 필요).
- **글꼴**: `noru358/watch` 리포의 `tools/artlab/fonts/Galmuri11.woff2`. 공개 리포라 `git clone --depth 1 https://github.com/noru358/watch.git`로 받아 쓴다.
- **확인용 봇**: 브라우저(Playwright, 미리 설치돼 있음)로 `agents.html`을 열고 `window.__sim(초, {mode: 'free' | 'auto' | 'manual'})`을 부른다. 하루마다 지표, 막힌 꼬물이 최대 수(`stuckMax`), 접수함이 찰 때 노는 수(`idleWhenFull`), 역할 배분을 돌려준다. **교착 0과 놓친 주문을 늘 확인한다.**
- **모듈 순서와 책임**: BLUEPRINT 5.3에 있다. 한 틱 순서는 `Flow.step`이다: 도착 → `Derive.refresh` → `Teams.tick` → `Crew.step`.
- **시제품 링크**(사용자 계정의 아티팩트): README 표에 있다. 현재 시제품은 https://claude.ai/artifact/R3qwGUoi3xDEH4YuXE7KUH 이다. 같은 링크로 갱신하려면 그 URL을 `url`로 주고 먼저 read한 뒤 publish한다.
- **막힌 접속**: github.io, odwo.kr(steamcity), wikipedia.org는 이 환경에서 직접 열리지 않았다. 공개 GitHub 리포는 git clone으로 받을 수 있다. 웹 검색은 된다.
- **이전 세션에서 쓴 개인 메모 위치**(스크린샷, 시뮬 스크립트)는 새 세션에 없다. 필요하면 다시 만든다.
